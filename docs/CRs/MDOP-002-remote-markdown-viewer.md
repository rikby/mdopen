# Remote Markdown viewer via encoded URL on GitHub Pages

## Problem

A user has a URL to a `.md` file and wants to view or share it as a styled,
printable mdopen page. GitHub renders its own Markdown, but other hosts serve
plain text, and none of them offer mdopen's themes, controls, and print
output.

## Solution

A GitHub Pages viewer page that embeds the target `.md` URL reversibly encoded
(base64url) in the URL fragment — no backend, consistent with the static
Pages architecture:

- `view.html` without a hash: shows a paste-URL form; normalizes GitHub blob
  URLs to raw, base64url-encodes the target, navigates to `#u=<encoded>`.
- `view.html#u=<encoded>`: decodes, `fetch()`es the Markdown, renders through
  the shared client-side pipeline (markdown-it + plugins, highlight.js,
  mermaid, frontmatter, callouts) into `.markdown-body`.

## Verified feasibility (2026-08-26)

- `raw.githubusercontent.com`, `gist.githubusercontent.com`,
  `cdn.jsdelivr.net/gh/...`, and `unpkg.com` all send
  `Access-Control-Allow-Origin: *` — direct cross-origin fetch works.
- `gitlab.com/.../-/raw/...` returns 200 with no ACAO header — browser
  Same-Origin Policy blocks the read; only a CORS proxy can reach it.
- base64url round-trips cleanly; typical shareable URL is ~130 chars.
- `edit.html` already proves the client-side rendering pipeline on Pages.

## Decisions

- No mdopen-side allowlist: any URL is accepted; the target server's own CORS
  header is the gate.
- Direct fetch first; on CORS failure show a clear error plus an opt-in
  "retry via public CORS proxy" action (no silent third-party routing).
- Force https for targets (mixed content would block plain http).
- GitHub Pages only: generated by `scripts/build-pages.js` like `edit.html`;
  must NOT enter the binary build (AGENTS.md editor rule applies).

## Open decisions

- HTML sanitization on the viewer path: remote Markdown renders with
  `html: true`, so a hostile host or tampering proxy can inject markup under
  the Pages origin. Options: CDN sanitizer (new dependency), raw-HTML off on
  the viewer path, or accept with a visible warning.

## Scope

- New: `view.html` generation in `scripts/build-pages.js`; a viewer browser
  script reusing `editor-script.html` machinery; paste-URL form.
- Docs: README and ARCHITECTURE updates for the viewer page.
- Tests: `bun run check`, `bun run build:pages`, manual Pages preview.
