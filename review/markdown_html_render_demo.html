Readable HTML from Markdown

A practical typography and color demo for markdown rendered as HTML. The same document should feel good on screen and remain clean when printed.

Design goals

A markdown-rendered page should be quiet, structured, and easy to scan. It should support long reading without fatigue and preserve clear hierarchy when printed.

  • Screen: comfortable contrast, generous spacing, soft color accents.
  • Print: strong contrast, simple borders, no dependence on background color.
  • Converter-friendly: normal HTML elements should look good without custom classes.

Color system

Use mostly neutral colors. Keep the accent color for links, heading emphasis, markers, and callout borders. The page should still work in grayscale.

Headings #

Headings use tighter line height and more space above than below. This helps readers see which paragraphs belong to each section.

Heading level 3 #

Third-level headings introduce subsections. They should be distinct, but not so large that the page feels fragmented.

Heading level 4

Fourth-level headings are useful for dense documentation. They stay close to the content they label.

Heading level 5

Fifth-level headings are compact. They work best inside reference-style content.

Heading level 6

Sixth-level headings are label-like. They should be rare.

Paragraphs and text semantics #

This is a normal paragraph. The line length is constrained so the reader does not need to scan across the full browser width. The line height is open enough for screen reading.

Markdown emphasis should remain simple: bold for importance, italic for nuance, and combined emphasis only when truly needed.

Extended markdown may produce deleted text, inserted text, highlighted text, small notes, abbreviations like HTML, superscript x2, and subscript H2O.

Links should look like links: example documentation link. In print, links become underlined black text.

Lists

Lists should be compact, aligned, and easy to scan.

  • Use modest spacing between items.
  • Keep markers quiet but visible.
    • Nested lists should not drift too far right.
    • Wrapped lines should align cleanly.

  • List items can contain paragraphs.

    The spacing should stay readable without making the list look broken.

  1. Write the core action first.
  2. Add context only when it helps.
  3. Keep related steps grouped together.

Blockquotes

Good typography does not ask the reader to notice the design. It removes friction from reading.

Nested quotes should remain readable and not become visually heavy.

The quote uses a left border and a soft background on screen. In print, the background disappears and the border carries the structure.

Callouts

Many markdown systems support callouts. If your converter does not, you can map blockquotes with labels like [!NOTE] into these blocks.

Note

Use notes for context, secondary explanation, or reading guidance.

Tip

Use tips for practical advice that improves the reader’s workflow.

Warning

Use warnings for risks, limitations, or decisions that need care.

Important

Use important blocks sparingly. Too many strong blocks weaken the hierarchy.

Code and technical inline elements

Inline code like font-size, line-height, and max-width should be readable without shouting. Keyboard input like Ctrl + K, sample output like Build completed, and variables like x should each have a clear treatment.

.markdown-body {
  max-width: 760px;
  margin: 0 auto;
  padding: 56px 64px;
  color: #1f2937;
  font-size: 18px;
  line-height: 1.65;
}

@media print {
  .markdown-body {
    max-width: none;
    padding: 0;
    color: black;
    box-shadow: none;
  }
}

Print behavior

The print stylesheet removes shadows, decorative page background, and most soft fills. It keeps hierarchy through size, rules, borders, and spacing.

  • Links are underlined.
  • Headings avoid page breaks directly after them.
  • Tables, figures, callouts, and code blocks try not to split across pages.
  • Code blocks switch to a light background to save ink.
